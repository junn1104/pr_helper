## Quick Start

> Flutter가 설치되어 있다는 가정하에 진행합니다.

### 1. Backend 설정

백엔드 폴더로 이동한 뒤 가상환경을 생성합니다.

```bash
python -m venv .venv
```

Windows PowerShell에서 가상환경을 활성화합니다.

```powershell
.\.venv\Scripts\Activate.ps1
```

필요한 패키지를 설치합니다.

```bash
pip install -r requirements.txt
```

기본적으로 `requirements.txt`에 포함된 패키지를 정상적으로 설치하면 별도의 추가 패키지 설치 없이 실행할 수 있습니다.

---

### 2. Backend 실행

아래 명령어로 FastAPI 서버를 실행합니다.

```bash
uvicorn app.main:app --reload
```

정상적으로 실행되면 아래 주소에서 서버 상태를 확인할 수 있습니다.

```text
http://127.0.0.1:8000/health
```

---

### 3. Frontend 실행

Flutter 프로젝트 폴더로 이동한 뒤 필요한 패키지를 설치합니다.

```bash
flutter pub get
```

Edge에서 실행하는 경우:

```bash
flutter run -d edge --web-port 5173
```

Chrome에서 실행하는 경우:

```bash
flutter run -d chrome --web-port 5173
```

---

### 4. 최초 실행 시 주의사항

PR Coach는 음성 분석을 위해 로컬 AI 모델을 사용합니다.

녹음된 WAV 파일을 업로드하거나 직접 녹음을 완료한 뒤 **최초 분석 요청이 들어오면 필요한 로컬 모델 다운로드가 자동으로 시작됩니다.**

```text
첫 분석 요청
      ↓
로컬 AI 모델 다운로드
      ↓
모델 로딩
      ↓
음성 분석 시작
```

최초 실행 시에는 모델 다운로드 및 로딩으로 인해 분석 시작까지 시간이 오래 걸릴 수 있습니다.

모델 다운로드가 한 번 정상적으로 완료되면 이후 실행부터는 로컬 캐시에 저장된 모델을 사용하므로 동일한 모델을 다시 다운로드하지 않습니다.

> **주의사항**
>
> - 최초 모델 다운로드 시 안정적인 네트워크 환경을 권장합니다.
> - 다운로드 도중 네트워크 연결이 끊기거나 프로그램이 종료될 경우 모델 다운로드가 실패할 수 있습니다.
> - 최초 실행 이후에는 캐시된 로컬 모델을 사용하므로 추가 다운로드 시간이 발생하지 않습니다.

---

### 5. 마이페이지(히스토리) 사용 방법

로그인/회원가입 없이 **기기별 익명 토큰**으로 사용자를 구분합니다.

앱 최초 실행 시 아래 API를 한 번 호출해 토큰을 발급받고,

```text
POST /api/device/register
→ { "token": "..." }
```

발급받은 토큰을 로컬(Flutter라면 `shared_preferences` 등)에 저장한 뒤,
이후 모든 요청 헤더에 그대로 실어 보냅니다.

```text
X-Device-Token: <발급받은 토큰>
```

- `POST /analyze` : 분석 결과를 반환하면서 해당 기기의 히스토리로 함께 저장합니다. (오디오 원본도 DB에 같이 저장됩니다.)
- `GET /api/history` : 이 기기가 분석했던 기록 목록(최신순)을 반환합니다.
- `GET /api/history/{id}` : 저장된 분석 결과 상세(`/analyze` 응답과 동일한 형태)를 반환합니다.
- `GET /api/history/{id}/audio` : 해당 기록의 원본 오디오를 반환합니다(다시듣기용).

토큰이 없거나 유효하지 않으면 위 4개 API는 모두 `401`을 반환하니,
`/api/device/register`를 먼저 호출해야 합니다.

DB는 기본적으로 로컬 SQLite 파일(`app.db`)을 사용하며,
배포 환경에서는 `.env`의 `DATABASE_URL`을 Postgres 접속 문자열로 바꾸면 됩니다.

# AI Presentation Coach

발표 음성의 **속도, 멈춤, 추임새, 반복 표현뿐만 아니라 음성의 감정·톤 변화까지 시간대별로 분석**하고,  
객관적인 분석 데이터를 기반으로 AI 코칭을 제공하는 발표 연습 서비스입니다.

단순히 발표 전체를 하나의 점수로 평가하는 것이 아니라,  
**약 15초 단위로 발표 흐름과 음성 톤의 변화를 함께 시각화**하여  
사용자가 어느 구간에서 발표 흐름이 달라졌는지 구체적으로 확인할 수 있도록 설계했습니다.

---

## 주요 기능

### 1. 발표 음성 STT 변환

SenseVoiceSmall 기반으로 발표 음성을 텍스트로 변환합니다.

- 한국어 발표 및 영어 표현 혼용 대응
- 발화 구간별 timestamp 추출
- 발표 전체 transcript 생성
- 변환된 발표 내용 복사 기능 제공

---

### 2. 감정 / 음성 톤 신호 분석

SenseVoice의 음성 감정 인식 결과를 활용해  
발표 중 나타나는 **음성 톤의 변화 신호를 시간대별로 분석**합니다.

전체 발표를 하나의 감정으로 단순 분류하지 않고,  
약 15초 단위로 음성을 나누어 각 구간의 톤 신호를 확인합니다.

예시:

- `neutral` → 차분한 톤
- `happy` → 밝은 톤
- `sad` → 가라앉은 톤
- `angry` → 강한 톤
- `fearful` → 불안정한 톤
- `surprised` → 변화가 큰 톤
- `disgusted` → 거친 톤

분석 신뢰도가 충분하지 않은 구간은  
`톤 신호 부족`으로 표시해 억지로 감정을 추정하지 않습니다.

> 이 기능은 발표자의 실제 감정 상태를 판단하기 위한 것이 아니라,  
> 음성에서 나타나는 감정/톤 관련 신호를 발표 피드백의 참고 정보로 활용합니다.

---

### 3. 발표 속도 분석

발표 전체의 속도와 실제 발화 구간의 속도를 구분해 분석합니다.

- 발표 전체 체감 속도
- 실제 발화 속도
- 전체 어절 수
- 발표 시간
- 실제 발화 시간

발표 속도는 5단계로 판정합니다.

- 느림
- 약간 느림
- 적절
- 약간 빠름
- 빠름

발표 속도 판정에는  
내부 멈춤을 포함한 발표 시간 기준의 속도를 사용합니다.

---

### 4. 멈춤 분석

WAV 음원의 RMS 값을 활용해 발표 중 무음 구간을 탐지합니다.

- 발표 시작 전 무음
- 발표 종료 후 무음
- 발표 내부 멈춤
- 전체 멈춤 시간
- 멈춤 비율
- 긴 멈춤 구간 탐지

자연스러운 짧은 호흡과 의미 있는 멈춤을 최대한 구분하기 위해  
현재 MVP에서는 일정 시간 이상 지속되는 무음 구간만 분석 대상으로 사용합니다.

---

### 5. 추임새 및 반복 표현 분석

Kiwi 형태소 분석을 활용해 발표 중 나타나는 추임새와 반복 표현을 탐지합니다.

추임새 예시:

- 음
- 그러니까
- 그

반복 표현이 탐지된 경우 발생 시간과 함께 기록합니다.

단, `어`, `아`와 같이 매우 짧은 추임새는  
STT 단계에서 생략될 수 있습니다.

---

### 6. 15초 단위 발표 흐름 분석

발표를 약 15초 단위로 나누어  
텍스트와 음성에서 추출한 여러 신호를 함께 분석합니다.

각 구간에서 다음 정보를 제공합니다.

- 발표 속도
- 멈춤 횟수
- 긴 멈춤 횟수
- 추임새
- 반복 표현
- 감정 / 음성 톤 신호
- 구간별 위험도

이를 통해 단순히

`전체 발표가 좋았다 / 나빴다`

라고 평가하는 것이 아니라,

- 언제 발표 속도가 빨라졌는지
- 어느 구간에서 멈춤이 많았는지
- 어느 시점에서 추임새가 증가했는지
- 어느 구간에서 음성 톤이 변화했는지

시간대별로 확인할 수 있습니다.

---

### 7. 구간별 위험도 시각화

각 15초 구간의 발표 데이터를 종합해  
구간별 위험도를 계산합니다.

위험도에는 다음 요소가 반영됩니다.

- 멈춤 횟수
- 긴 멈춤
- 추임새
- 반복 표현
- 발표 속도

화면에서는 다음과 같이 표시합니다.

- `안정`
- `보통`
- `주의`

사용자는 타임라인의 각 구간을 선택해  
해당 시간대의 상세 분석 결과를 확인할 수 있습니다.

---

### 8. 객관적인 강점 탐지

AI가 임의로 장점을 생성하지 않도록  
별도의 `StrengthAnalyzer`를 사용해 객관적인 강점 신호를 먼저 추출합니다.

예시:

- 전체 발표 속도가 적절한 경우
- 전체 발표에서 반복 표현이 없는 경우
- 전체 발표에서 추임새가 없는 경우
- 일정 시간 이상 안정적인 발표 흐름을 유지한 경우
- 일정 시간 동안 적절한 속도를 유지한 경우
- 일정 시간 동안 멈춤이 적은 경우

이 데이터를 Gemini에 전달해  
실제 분석 근거가 있는 강점만 코칭에 반영합니다.

---

### 9. AI 발표 코칭

Gemini를 활용해 분석된 정량 데이터를 기반으로 발표 코칭을 생성합니다.

제공되는 내용:

- AI 종합 평가
- 잘한 점
- 개선할 점
- 다음 연습 목표
- 한 줄 코칭

Gemini가 분석 결과에 없는 내용을 임의로 생성하지 않도록  
프롬프트에 강한 제한을 적용했습니다.

예를 들어 다음과 같은 내용을 분석 근거 없이 생성하지 않도록 제한합니다.

- 발음이 좋았다
- 자신감이 있었다
- 청중 반응이 좋았다
- 준비가 잘 되어 있었다
- 발표자의 실제 감정 상태

즉, AI는 발표를 직접 평가하는 역할보다  
**실제 분석 데이터를 이해하기 쉬운 코칭 문장으로 변환하는 역할**을 수행합니다.
